# Internationalization

Blunder-Tutor keeps interface copy in flat JSON dictionaries under `locales/`. English is the source locale. The server and browser use matching, deliberately small formatters for placeholders and plurals.

Supported locales are `en`, `ru`, `uk`, `es`, `pl`, `be`, and `zh`. A locale is available only when its JSON file exists.

## Runtime flow

```text
locales/*.json
      │ loaded at startup
      ▼
TranslationManager
      │
      ├── request.state.t ──► Jinja2 {{ t('key') }}
      │
      └── merged dictionary ──► window.__i18n__ ──► t('key', params)
```

| Part | Source |
|---|---|
| Translation loading and server formatting | `blunder_tutor/i18n/manager.py` |
| Locale selection | `LocaleMiddleware` in `blunder_tutor/web/middleware.py` |
| Jinja2 context | `blunder_tutor/web/template_context.py` |
| Browser formatting | `blunder_tutor/web/static/js/i18n.js` |
| TypeScript global declarations | `frontend/src/vendor.d.ts` |
| Locale setting endpoint | `POST /api/settings/locale` |
| Tests | `tests/test_i18n.py` |

`TranslationManager` merges the selected dictionary over English before sending it to the browser. A missing localized key therefore falls back to English. A key missing from English too is rendered as the key itself, making the mistake visible.

## Using translations

### Jinja2

```html
<h1>{{ t('trainer.title') }}</h1>
<p>{{ t('trainer.blunder.cp_loss', loss='2.3') }}</p>
```

### TypeScript and browser scripts

`t`, `formatNumber`, and `formatDate` are globals loaded by `templates/base.html` before page islands mount.

```tsx
<Button>{t('trainer.button.submit')}</Button>
<p>{t('heatmap.total', { count: 5 })}</p>
<span>{formatNumber(1234.5)}</span>
<time>{formatDate(date, { dateStyle: 'long' })}</time>
```

Keep markup in JSX or templates. Translation values contain text, not HTML.

Do not build sentences from translated fragments. Translate one complete sentence and pass changing values as parameters:

```json
"trainer.feedback.same_blunder_detail": "{userMove} repeats the move from the game."
```

## Supported message syntax

This is not a complete ICU MessageFormat implementation. Both formatters support only:

- placeholders: `"Hello {name}"`
- one plural expression with flat CLDR-style branches
- exact non-negative integer branches such as `=0`
- `#` substitution inside a plural branch

```json
"heatmap.total": "{count, plural, =0 {No puzzles} one {# puzzle} other {# puzzles}}"
```

Use non-negative integer counts, include an `other` branch, and pass the parameter object when formatting; otherwise the plural expression remains literal. Do not use multiple plural blocks, select expressions, offsets, rich text, or nested plural/select structures. Python and JavaScript parse multiple blocks differently. If the syntax changes, update and test both `manager.py` and `i18n.js`.

Plural rules currently exist for the seven shipped locales. `manager.py` also contains dormant German and French rules, but those languages are not available without locale files.

## Locale selection and persistence

`LocaleMiddleware` chooses the locale from:

1. a supported `locale` cookie;
2. the current user's cached value;
3. a supported persisted `app_settings.locale` value;
4. the first supported base language in `Accept-Language`;
5. English.

The cache value is not revalidated against the loaded catalogs. `Accept-Language` region suffixes are stripped, but quality weights are ignored. The cookie is browser-wide and takes precedence over per-user settings when accounts share a browser.

`POST /api/settings/locale` validates the locale, stores it in the current user's application database, updates the per-user cache, and sets the cookie for one year. The Settings island then reloads the page. Data wipe preserves settings, including the locale.

## Adding or changing copy

1. Add the key to `locales/en.json`.
2. Add the same key with a real translation to every other shipped locale.
3. Call `t()` at the rendering boundary.
4. Run `uv run pytest tests/test_i18n.py -v` and the relevant frontend test.

Use stable, descriptive names grouped by feature, for example:

```text
common.loading
nav.settings
chess.phase.opening
trainer.feedback.excellent
settings.locale.description
```

Names describe meaning, not the current English wording. Search before adding a key; reuse an existing key only when its meaning and context match.

For API failures, prefer a stable backend error slug and translate it in the browser. `frontend/src/shared/translate-api-error.ts` shows the auth pattern. Do not expose exception text as translated interface copy.

## Adding a locale

1. Copy `locales/en.json` to `locales/<code>.json` and translate every value.
2. Add its native display name to `LOCALE_DISPLAY_NAMES` in `web/template_context.py`.
3. If its plural behavior is new, add the same rule to `PLURAL_RULES` in both `i18n/manager.py` and `static/js/i18n.js`.
4. Add server tests for its plural categories and fallback behavior.
5. Verify key parity:

```bash
python - <<'PY'
import json
from pathlib import Path

files = sorted(Path('locales').glob('*.json'))
expected = set(json.loads(Path('locales/en.json').read_text()))
for path in files:
    keys = set(json.loads(path.read_text()))
    assert keys == expected, f'{path}: missing={expected - keys}, extra={keys - expected}'
print(f'{len(files)} locale files match')
PY
```

The Settings selector discovers the locale from its filename; there is no separate registry of enabled locales. Catalog loading has no schema validation, so the parity check above and focused plural tests are required. A malformed JSON file prevents locale loading at startup.

## Translation pitfalls

- Use plural syntax whenever a number controls a noun form.
- Preserve placeholder names exactly across locales.
- Format numbers and dates with `formatNumber` and `formatDate`, not string concatenation.
- Avoid gender-dependent sentence shapes when a placeholder may contain different chess pieces.
- Explanation text uses case-specific piece keys such as `.gen`, `.acc`, and `.inst`; preserve those variants. `blunder_tutor/utils/explanation.py` produces `I18nMessage` values and resolves them only after the request locale is known.
- Validate Slavic grammar as a sentence. Word-for-word substitution is not enough.

## Maintenance

Do not record key counts or exhaustive namespace lists here; the JSON files are the source of truth. Update this guide when locale resolution, supported message syntax, or the server/browser integration changes.
